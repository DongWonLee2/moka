# ADR-0007: 마이그레이션 이름 시험은 GRDB 등록 목록을 직접 본다 (ADR-0004 일부 대체)

- 상태: Accepted
- 작성일 / 사람 승인일: 2026-10-28 / 2026-10-28
- 결정 책임자: 저장소 소유자
- 관련 Spec/R-ID: spec 001 R-012, ADR-0004 "Agent의 추천과 근거"의 마이그레이션 이름 목록 항목
- 대체 범위: ADR-0004의 문장 "GRDB 문서에 등록 목록을 읽는 API가 없으므로 이름 배열 상수로 등록하고 그 상수를 시험한다"만 대체한다. ADR-0004의 나머지(이름 목록 고정·덧붙이기만, 스냅샷 비교, erase 금지, 가드 테스트)는 그대로다.
- 사용한 외부 근거: GRDB 7.11.1 소스 `GRDB/Migration/DatabaseMigrator.swift` 491~494행

## 맥락

ADR-0004는 GRDB에 등록된 마이그레이션 목록을 읽는 API가 없다고 보고, 이름 배열 상수를 시험하기로 했다. spec 001 EGM 금붕어 리뷰(2026-10-28)에서 이 전제가 틀렸다는 지적이 나왔다. 확인해 보니 GRDB 7.11.1(`Package.swift`에 `exact: "7.11.1"`)에 아래 API가 있다.

```swift
/// The list of registered migration identifiers, in the same order as they
/// have been registered.
public var migrations: [String]
```

등록 코드와 시험이 같은 상수를 쓰면, 그 시험은 상수가 자기 자신과 같다는 것만 확인한다. 상수와 실제 `registerMigration` 호출이 어긋나도 PASS가 나므로 거짓 PASS다(ADR-0004 평가 기준 4).

## 평가 기준

1. 거짓 PASS가 없는가 2. 등록 누락·순서 오류를 잡는가 3. 사용자 규칙("채택된 ADR을 바꾸려면 새 ADR", AGENTS.md)을 지키는가

## 대안

| 대안 | 장점 | 단점·위험 |
|---|---|---|
| A. 새 ADR로 정정 + ADR-0004 해당 문장 옆에 포인터 | 사용자 규칙을 글자 그대로 지킴, 이력이 남음 | 문서 하나 늘어남 |
| B. ADR-0004 안에 날짜 붙인 정정 줄 | 문서 수 그대로 | "사실 정정은 예외"라는 해석을 허용해 결정을 제자리에서 바꾸는 길이 열림 |
| C. 그대로 둠 | 일 없음 | 틀린 전제를 다음 세션이 사실로 읽음, 자기 비교 시험 |

## Agent의 추천과 근거

A를 추천한다(추천안 토론 3:0, 3라운드).
- 시험은 시험 파일 안에 적은 리터럴 `["v1_settings"]`와 `MokaMigrations.migrator.migrations`가 같은지 단언한다. 등록에 쓰는 상수와 비교하지 않는다.
- 새 마이그레이션을 더할 때는 이 리터럴에 이름을 덧붙인다(덧붙이기만 허용, ADR-0004 그대로).

## 사람의 최종 결정과 실제 판단 이유

Agent 추천안 채택. 판단 이유: 사용자 위임(토론 채택안 선택, 2026-10-28)

## 포기하는 것·운영 영향

- 트레이드오프: 이름이 두 곳(등록 코드, 시험 리터럴)에 적힌다. 그 중복이 시험이 의미를 갖는 이유다.
- 되돌리기: 쉬움(시험 한 줄).

## 결정 검증

- 실행할 실험: 가짜 마이그레이션 하나를 더 등록하거나 이름을 바꾼 뒤 이름 시험이 FAIL하는지 확인한다(커밋하지 않음, spec 001 quickstart 3).
- 성공 판정: 주입 시 FAIL, 원복 시 PASS.
- 재검토 트리거: GRDB 버전 변경으로 `migrations` API가 바뀜.
