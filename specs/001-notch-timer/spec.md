# Feature Specification: 노치와 타이머 (마일스톤 1)

**Feature Branch**: `chore/spec-001-notch-timer`

**Created**: 2026-10-28

**Status**: Draft

**Input**: PRD 12장 마일스톤 1 "노치와 타이머" — FR-06(collapsed, expanded 일부), FR-16(`default_quantum_min`). FR-05(시간 칩)는 PRD 12장에서 마일스톤 4지만, 완료 조건의 "사용자가 고른 시간"에 필요해 칩 기본형만 앞당겼다. 완료 조건: 노치에 수동 입력한 할 일 하나와 사용자가 고른 시간의 타이머가 뜬다. 범위는 사용자와 2026-10-28에 정했다(grilling 질문 12개, 결정 로그 `.audit/day0.tsv`, 커밋 안 함).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 할 일 하나를 넣고 타이머를 돌린다 (Priority: P1)

사용자는 노치에 마우스를 올려 펼치고, 할 일 제목을 입력한 뒤 작업 시간을 고르고 시작한다. 그 뒤로는 노치를 접어 두어도 제목과 남은 시간이 보인다. 다 했으면 완료를 눌러 비운다.

**Why this priority**: 마일스톤 1의 완료 조건 그 자체다. 이것만 있어도 "지금 할 일 하나와 남은 시간"이라는 제품의 핵심 화면이 생긴다.

**Independent Test**: 빈 상태에서 제목 입력 → 시간 선택 → 시작 → 접힌 화면에 제목과 줄어드는 남은 시간이 보이는지 → 완료 → 빈 상태로 돌아오는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 할 일이 없다, **When** 접힌 노치를 본다, **Then** 회색 점 하나만 보인다.
2. **Given** 할 일이 없다, **When** 노치에 마우스를 올린다, **Then** 펼친 화면에 제목 입력칸이 보이고, 키보드 입력은 계속 원래 앱으로 간다.
2a. **Given** 마우스를 올려 펼친 화면이다, **When** 펼친 화면을 클릭한다, **Then** 제목 입력칸에 포커스가 가서 바로 타이핑할 수 있다.
3. **Given** 입력칸에 "가짜 할 일 A"를 입력했다, **When** Enter를 누른다, **Then** 시간 칩이 설정 기본값(초기 25분)으로 미리 채워져 보인다.
4. **Given** 칩이 25분으로 채워져 있다, **When** 시작을 누르거나 Enter를 누른다, **Then** 25:00부터 타이머가 줄어들고, 접힌 화면에 점·제목·남은 시간이 보인다(제목이 길면 끝을 "…"로 줄임).
5. **Given** 타이머가 도는 중이다, **When** 펼친 화면을 연다, **Then** 제목, 남은 시간, 완료 버튼만 보인다.
6. **Given** 타이머가 도는 중이다, **When** 완료를 누른다, **Then** 타이머가 멈추고 빈 상태(회색 점)로 돌아간다.

---

### User Story 2 - 작업 시간을 바꿔 고른다 (Priority: P1)

사용자는 기본값이 아닌 시간으로 일하고 싶을 때 칩을 눌러 다른 길이를 고르거나 직접 입력한다.

**Why this priority**: 완료 조건의 "사용자가 고른 시간"이다. US1과 함께 있어야 마일스톤이 끝난다.

**Independent Test**: 칩을 펼쳐 45분을 고르고 시작해 45:00부터 줄어드는지, 직접 입력 0과 181이 거부되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 칩이 기본값으로 채워져 있다, **When** 칩을 누른다, **Then** 15/25/45/60분과 직접 입력이 펼쳐진다.
2. **Given** 칩이 펼쳐져 있다, **When** 45분을 고르고 시작한다, **Then** 45:00부터 줄어든다.
3. **Given** 직접 입력을 골랐다, **When** 90을 입력한다, **Then** 시작할 수 있고 1:30:00부터 줄어든다.
4. **Given** 직접 입력을 골랐다, **When** 0, 181, 빈 값, 숫자가 아닌 값을 입력한다, **Then** 시작 버튼이 막혀 있다.

### User Story 3 - 시간이 끝나면 알아챈다 (Priority: P1)

타이머가 0:00이 되면 노치가 저절로 펼쳐져 "시간 끝"을 보여 준다. 사용자는 같은 일을 다시 시작하거나 완료한다.

**Why this priority**: 시간이 끝난 걸 모르면 타이머의 의미가 없다. 소리와 알림을 쓰지 않으므로 화면이 유일한 신호다.

**Independent Test**: 1분 타이머를 시작하고 만료 시 노치가 펼쳐지는지, 다른 앱에서 타이핑하던 글자가 노치로 들어가지 않는지, 마우스를 움직여도 접히지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 타이머가 도는 중이다, **When** 남은 시간이 0이 된다, **Then** 타이머는 0:00에서 멈추고 노치가 자동으로 펼쳐져 "시간 끝", 시간 칩, 완료 버튼을 보여 준다.
2. **Given** 시간 끝으로 자동 펼쳐졌다, **When** 사용자가 다른 앱에서 계속 타이핑한다, **Then** 글자는 그 앱에 들어가고 노치로 가지 않는다.
3. **Given** 시간 끝으로 자동 펼쳐졌다, **When** 마우스가 노치 위로 들어왔다 나간다, **Then** 펼친 상태가 유지된다.
4. **Given** 시간 끝 상태다, **When** 칩에서 시간을 고르고 시작한다, **Then** 같은 할 일로 그 시간만큼 타이머가 다시 돈다.
5. **Given** 시간 끝 상태다, **When** 완료를 누른다, **Then** 빈 상태로 돌아간다.

---

### User Story 4 - 기본 작업 시간을 설정한다 (Priority: P2)

사용자는 메뉴 막대의 "설정…"에서 기본 작업 시간을 바꾼다. 다음에 할 일을 넣을 때 칩이 그 값으로 채워진다.

**Why this priority**: FR-16 일부다. 없어도 칩으로 매번 고를 수 있으므로 P1보다 낮다.

**Independent Test**: 기본값을 45로 바꾼 뒤 새 할 일을 넣어 칩이 45분으로 채워지는지, 이미 도는 타이머는 그대로인지 확인한다.

**Acceptance Scenarios**:

1. **Given** 기본값이 25분이다, **When** 설정에서 45분으로 바꾸고 새 할 일 제목을 입력한다, **Then** 칩이 45분으로 채워진다.
2. **Given** 25분 타이머가 도는 중이다, **When** 기본값을 45분으로 바꾼다, **Then** 도는 타이머의 남은 시간은 바뀌지 않는다.
3. **Given** 설정 화면이다, **When** 1~180 밖의 값을 넣는다, **Then** 저장되지 않고 이전 값이 유지된다.
4. **Given** 기본값을 45분으로 바꿨다, **When** 앱을 다시 켠다, **Then** 기본값은 45분이다.

---

### User Story 5 - 노치가 없는 화면에서도 보인다 (Priority: P2)

외부 모니터만 쓰거나 노치가 없는 맥에서는 메뉴 막대 아래 중앙에 작은 떠 있는 창으로 같은 내용(제목과 남은 시간)을 보여 주고, 마우스를 올리면 펼친다.

**Why this priority**: FR-06 수용 기준("외부 모니터에서 플로팅으로 표시")이다. 사용자의 주 사용 환경은 노치가 있는 내장 화면이라 P1보다 낮다.

**Independent Test**: 덮개를 닫고 외부 모니터만 연결한 상태에서 할 일을 넣고 타이머를 돌려 떠 있는 창에 제목과 남은 시간이 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 노치가 있는 내장 화면과 외부 모니터가 함께 연결되어 있다, **When** 앱을 켠다, **Then** 내장 화면의 노치에 표시한다.
2. **Given** 외부 모니터만 연결되어 있다, **When** 앱을 켠다, **Then** 주 화면의 메뉴 막대 아래 중앙에 떠 있는 창으로 표시한다.
3. **Given** 떠 있는 창이 접혀 있다, **When** 마우스를 올린다, **Then** 펼친 화면이 나온다(내용은 노치와 같다).
4. **Given** 노치에 표시 중이다, **When** 덮개를 닫아 외부 모니터만 남는다, **Then** 표시가 주 화면의 떠 있는 창으로 옮겨가고 타이머는 끊기지 않는다.

---

### Edge Cases

- **잠자기:** 25분 타이머 중 맥이 10분 잠들었다 깨면 남은 시간은 10분 줄어 있다. 자는 동안 끝 시각이 지났으면 깨어나자마자 "시간 끝"으로 자동 펼친다(R-008).
- **시계 변경:** 시간대가 바뀌어도 남은 시간은 그대로다. 사용자가 시스템 시각을 바꾸면 끝 시각 기준이라 그만큼 남은 시간이 바뀐다. 앞당겨 끝 시각이 지나면 시간 끝이고, 되돌려도 남은 시간은 고른 작업 시간을 넘지 않는다.
- **빈 제목:** 공백만 있는 제목은 Enter를 눌러도 다음 단계로 가지 않는다.
- **긴 제목:** 접힌 화면에 들어가지 않는 제목은 끝을 "…"로 줄인다. 펼친 화면에는 두 줄까지 보인다.
- **메뉴 막대 겹침:** 메뉴가 노치 너머까지 넘치는 앱(예: Xcode)에서는 접힌 노치 띠가 노치 바로 옆 메뉴 몇 개를 가린다. 사용자가 제목을 보는 쪽을 택했다(2026-10-28 시안 검토).
- **앱 재시작:** 도는 타이머와 할 일은 사라지고 빈 상태로 시작한다. 기본값 설정은 남는다.
- **설정 값 경계:** R-004의 받는 값·거부 값과 같다.
- **입력 중 마우스 이탈:** 제목이나 직접 입력을 치는 도중 마우스가 노치 밖으로 나가도 입력칸에 포커스가 있으면 접지 않는다.
- **지나가는 마우스:** 다른 앱에서 타이핑하다가 마우스가 노치를 지나가 펼쳐져도 글자는 원래 앱으로 간다(R-002 포커스 규칙).
- **화면 연결 변경:** 화면을 연결하거나 분리하면 R-011 규칙으로 표시 위치를 다시 고른다. 타이머 상태는 바뀌지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

| R-ID | 요구 | PRD |
|---|---|---|
| R-001 | 할 일이 없을 때 접힌 화면은 회색 점 하나만 보이고, 마우스를 올리면 펼친 화면에 제목 입력칸(자리표시 "할 일 없음 — 무엇을 할까요?")을 보여야 한다 | FR-06 |
| R-002 | 사용자는 펼친 화면의 입력칸에 제목을 넣고 Enter로 시간 선택 단계로 갈 수 있어야 한다. 앞뒤 공백을 뺀 제목이 비어 있으면 넘어가지 않는다. 마우스를 올려 펼칠 때는 키보드 포커스를 가져가지 않아야 하고, 사용자가 펼친 화면을 클릭하면 포커스를 받아 빈 상태면 제목 입력칸에 둔다(사용자 결정 2026-10-28) | FR-06 |
| R-003 | 시간 칩은 설정 기본값(`default_quantum_min`)으로 미리 채워지고, 시간 고르기 화면에서는 Enter나 시작 한 번으로 그 값으로 시작해야 한다. 시간 끝 화면에서도 칩은 기본값으로 채워지지만 Enter(기본 버튼)는 완료이고, 다시 시작은 버튼으로만 한다. 예외로 시간 끝 화면에서 직접 입력 칸이 열려 있는 동안은 Enter가 다시 시작이다(사용자 결정 2026-10-29, PR #33) | FR-05 |
| R-004 | 칩을 누르면 15/25/45/60분과 직접 입력이 펼쳐져야 한다. 직접 입력은 1~180 사이 정수만 받아야 하고, 0, 181, 소수, 빈 값, 숫자가 아닌 값이면 시작을 막는다 | FR-05 |
| R-005 | 할 일은 동시에 하나만 있어야 한다. 시작하면 고른 시간만큼 타이머가 돌고, 남은 시간은 끝 시각에서 현재 시각을 뺀 값이어야 한다(잠자기는 반영되고, 시계를 되돌려도 고른 작업 시간을 넘지 않는다) | FR-06 |
| R-006 | 타이머가 도는 동안 접힌 화면은 점·제목·남은 시간을 보이고(노치 왼쪽 폭 104pt, 넘치는 제목은 끝을 "…"로), 펼친 화면은 제목(두 줄까지)·남은 시간·완료 버튼만 보여야 한다 | FR-06 |
| R-007 | 완료를 누르면 (도는 중이든 시간 끝이든) 할 일을 비우고 빈 상태로 돌아가야 한다 | FR-06 |
| R-008 | 남은 시간이 0이 되면 0:00에서 멈추고 "시간 끝" 상태가 된다. 노치를 자동으로 펼쳐 "시간 끝", 시간 칩, 시작·완료 버튼을 보인다. 자는 동안 끝났으면 깨어날 때 같은 상태를 보인다. 소리·시스템 알림·자동 연장은 없다 | FR-06 |
| R-009 | 시간 끝으로 자동 펼친 화면은 키보드 포커스를 가져가지 않고, 마우스가 나가도 사용자가 시작 또는 완료를 누를 때까지 펼친 채로 남아야 한다 | FR-06 |
| R-010 | 시간 끝 상태에서 칩으로 시간을 고르고 시작하면 같은 할 일로 타이머가 다시 돌아야 한다 | FR-05 |
| R-011 | 표시 위치는 노치가 있는 내장 화면을 우선한다. 그런 화면이 없으면 주 화면의 메뉴 막대 아래 중앙에 떠 있는 창으로 같은 접힘·펼침 내용을 보인다. 화면 연결이 바뀌면 다시 고르고, 타이머는 끊기지 않는다 | FR-06 |
| R-012 | 메뉴 막대 항목은 "설정…"과 "종료"만 가진다. 펼친 판의 우클릭 메뉴에도 "설정…"과 "종료"를 둔다(메뉴 막대가 넘치면 macOS가 아이콘을 노치 뒤로 숨기는 동작 대비). 설정 화면에서 `default_quantum_min`(기본 25, 1~180 정수)을 바꿀 수 있고, 바꾼 값은 앱을 다시 켜도 남는다 | FR-16 |
| R-013 | 기본값 변경은 다음에 칩을 채울 때 바로 반영되고, 이미 도는 타이머에는 영향이 없어야 한다 | FR-16 |
| R-014 | 할 일과 타이머는 메모리에만 둔다. 앱을 다시 켜면 빈 상태로 시작한다 | (마일스톤 2에서 FR-01 저장) |
| R-015 | 화면 없이 확인하는 시뮬레이터는 할 일 입력, 시간 선택, 시각 경과, 완료 같은 이벤트 목록을 받아 상태 변화(빈 상태 → 도는 중 → 시간 끝 → 빈 상태)와 각 시점의 남은 시간을 출력해야 한다 | ADR-0003 검증 경로 |

### Key Entities

- **현재 할 일**: 제목 하나. 동시에 최대 1개. 저장하지 않는다.
- **타이머**: 상태(빈 상태 / 도는 중 / 시간 끝), 고른 길이(분), 시작 시각, 끝 시각. 남은 시간은 끝 시각과 현재 시각으로 계산한다.
- **기본 작업 시간 설정**: `default_quantum_min` 정수 하나(1~180, 초기 25). 재시작 뒤에도 남는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 빈 상태에서 기본 시간으로 타이머를 시작하기까지 제목 타이핑 외 조작은 마우스 올리기 1번, 클릭 1번, Enter 2번이다(사용자 결정 2026-10-28, 클릭 1번 추가).
- **SC-002**: (a) 남은 시간 계산은 끝 시각 기준이며 잠자기를 끼워도 맞다 — `moka-sim`과 주입한 시계로 확인한다. (b) 끝 시각에서 시간 끝 화면이 보이기까지의 지연은 사람이 quickstart 6에서 눈으로 본다.
- **SC-003**: 시간 끝 순간, 그리고 마우스가 노치를 지나갈 때 다른 앱에서 타이핑하던 글자가 노치에 한 글자도 들어가지 않는다.
- **SC-004**: 펼침과 접힘이 사람 눈에 바로 반응한다(PRD 기준 100ms, 이번에는 사람이 눈으로 확인한다. 계기 측정 결과는 NOT_RUN으로 적고 버퍼 기간 11/8~9에 잰다).
- **SC-005**: 외부 모니터만 연결한 상태에서도 제목과 남은 시간이 보인다.
- **SC-006**: 시뮬레이터로 R-003·R-005·R-007·R-008·R-010·R-013의 상태 변화를 화면 없이 재현할 수 있다. 시계 되돌림(R-005)은 시뮬레이터가 시각 역행을 입력 오류로 막으므로 단위 시험으로 확인한다.

## Assumptions

- 사용자는 작성자 1인이고 macOS 14 이상, 주 환경은 노치가 있는 내장 화면이다.
- 화면 디자인은 사용자가 2026-10-28 "시안 확정"한 HTML 시안 v3.5를 따른다: `~/Dev/ai-platform/projects/moka/design/001-mockup.html`(저장소 밖, 로컬 전용). 요점:
  - 화면에 보이는 이름은 Moka. 아이콘은 넓은 잔 + 김 한 줄(시안 9번 S3), 메뉴 막대는 단색 템플릿 이미지.
  - 메인 색은 PANTONE 17-1230 모카 무스(sRGB 근사 #A47864). 기본 버튼·선택 칸은 #A47864→#85604F, 보조 크레마 #E6C7B4, 폼 #F5E9E1, 시간 끝 #E5533D. 메뉴 강조색은 시스템 강조색.
  - 시간 선택은 macOS 분할 컨트롤(15분|25분|45분|60분|직접…), 버튼은 둥근 사각형 push button.
  - 펼친 판(폭 340pt)의 노치 양옆 검정 자리: 왼쪽은 모카 무스색 잔 + 폼색 MOKA 워드마크, 오른쪽은 상태 글자(새 할 일 / 시간 고르기 / N분 집중 / 시간 끝).
  - 펼친 판·접힌 띠 위쪽 양 끝은 안쪽으로 오목한 곡선(8pt)이다.
  - 노치 위치, 애니메이션, hover 반응은 그림으로 볼 수 없어 구현 뒤 사람이 확인한다.
- 떠 있는 창은 위치를 고정하고 드래그를 넣지 않는다(PRD 13장 미결 사항은 그대로 둔다).
- 시간 끝 화면은 버튼을 누를 때까지 펼쳐 둔다. 화면을 계속 가리는 문제가 생기면 "N분 뒤 접기"를 마일스톤 2 이후에 다룬다.
- 직접 입력 상한 180분은 에이전트가 제안하고 사용자가 grilling에서 받아들인 값이다.
- 기본값 설정의 저장 위치와 시뮬레이터 입력 형식은 승인 항목이라 plan에서 정한다(헌법 I).

## Non-Goals

- 이유, 다음 2개, 미루기, 바꿔줘, 체크포인트(FR-07), 할 일별 마지막 선택, 예상 소요, 일시 중지(FR-20), 할 일 저장(FR-01), 판단 질의, 이월 카드는 이번 범위 밖이다(마일스톤 2~4).
- PRD NFR "앱 크래시 시 다음 실행에서 현재 할 일과 타이머 복구"는 이번에 지키지 않는다(R-014). 저장이 생기는 마일스톤 2에서 다룬다.
- 소리, 시스템 알림, 자동 연장, 떠 있는 창 드래그, 완료 되돌리기, 종료 확인은 넣지 않는다.

## 대안과 위험

- 대안: 타이머 모델(끝 시각 vs 1초 카운터, monotonic 시계)은 [research.md](research.md) R1, 저장(GRDB vs UserDefaults)은 R2, 노치 라이브러리와 떠 있는 창은 R4·R5, 시간 끝 신호(자동 펼침 vs 소리·알림)와 메뉴 막대 겹침 허용은 위 Edge Cases와 grilling 결정.
- 위험 1: 노치 모양과 열고 닫는 애니메이션을 라이브러리 없이 직접 만든다(spike 뒤 DynamicNotchKit 제외, ADR-0008). 같은 원인으로 두 번 사람 확인에 미달하면 라이브러리로 되돌린다(ADR-0008 되돌림 조건).
- 위험 2: 앱 DB를 열지 못하면 메모리 저장소로 동작하고 오류를 로그에 남긴다. 이때 기본값은 재시작 뒤 남지 않는다.
- 알려진 위험(이번에 다루지 않음): 다른 Space·전체 화면 앱·화면 공유 중 표시와 시간 끝 자동 펼침. 화면 공유 중 자동 펼침은 할 일 제목을 보일 수 있다.
- 알려진 위험(관찰, 2026-10-28 spike): 메뉴 막대 항목이 넘치면 macOS가 일부 앱 아이콘을 노치 뒤로 숨긴다(공식 문서 없음). Moka 아이콘이 숨으면 메뉴 막대로 설정·종료에 갈 수 없어 R-012 우클릭 메뉴로 대비한다. nonactivating 패널에서 우클릭 메뉴가 뜨지 않거나 설정 창이 앞으로 오지 않으면(T032 사람 확인) 이 위험은 그대로 남는다.
