# Data Model: 일시 중지와 급한 일 끼워 넣기 (spec 008)

규칙, 값, 모양의 원본이다. 이름은 [GLOSSARY.md](../../GLOSSARY.md)를 따르고, 새 코드 이름은 이 문서가 처음 정한다(research R19). 기준 `origin/main` `2629d8c`. `(Pn)` 표시는 [research.md](research.md)의 정한 결정이다(토론 3:0, 2026-11-18).

## §1 일시 중지 상태 (R-801~R-807)

메모리에만 둔다(R-807). 저장하지 않는다.

```swift
// NotchTimer에 더하는 case(P1). 남은 초와 고른 분의 원본은 여기 한 곳이다.
case paused(title: String, quantumMin: Int, remaining: TimeInterval)

enum PauseLength: Equatable, Sendable {
    case minutes(Int)     // Defaults.quantumMinRange 안(P10)
    case untilMorning     // "내일 아침까지"
}

enum PauseOrigin: Equatable, Sendable {
    case run              // 도는 중에서 멈춤. 할 일은 session.taskID, 하루는 session.run.budgetDay가 원본이다
    case draft            // 초안에서 멈춤. 타이머는 .empty(draft:) 그대로다
}

enum PauseStage: Equatable, Sendable {
    case choosing                   // 길이를 고르는 중
    case notes(PauseLength)         // 두 줄을 적는 중(도는 중에서 멈췄을 때만)
    case holding(endsAt: Date)      // 멈춤. now ≥ endsAt이면 길이가 끝나 기다리는 중
}

struct PauseState: Equatable, Sendable {
    var origin: PauseOrigin
    var stage: PauseStage
    var pausedDay: LocalDay         // 누른 때의 하루(R-806 판정)
}
```

- 소유: `NotchSession.pause: PauseState?`다. 일시 중지 중이 아니면 nil이고, init 인자에 기본값을 두지 않아 세션을 만드는 자리를 컴파일러가 잡는다(`urgent`와 같다, §9). 시험의 생성 자리는 단위 1에서 기계적으로 고친다.
- `SessionAssembly.activate`의 입출력은 그대로다. 세션을 받아 `Activated`를 돌려주고, `session.pause`를 읽어 모드에 넘긴다. 하루 경계 끝내기는 그 안에서 하지 않는다(§4).
- `session.run`은 멈춘 동안 그대로 둔다. `lifecycleCheckpoint`와 경과 분 계산이 `run`을 본다. 이어 돌 때 `run.startedAt`과 타이머의 시작 시각을 §3 식으로 함께 바꾼다.
- `NotchSession.swift:5`의 주석("타입과 기존 golden은 바꾸지 않는다")을 고친다. 타입은 바뀌고, 새 이벤트가 없는 시나리오의 golden만 바이트 그대로다.
- 초안 멈춤은 타이머가 `.empty`라 타이머만 보고는 알 수 없다. `NotchMode.of`와 `SessionAssembly.mode`는 일시 중지 인자를 기본값 없이 받는다(P1).
- 끝 시각: `.minutes(m)`은 두 줄을 마친 시각 + m분, 초안이면 길이를 고른 시각 + m분이다. `.untilMorning`은 `DayBoundary.start(of: 그때의 하루 + 1일)`이다. 05:00에 고르면 그 시각의 하루는 전날이라 그날 06:00에 끝난다(US1-12).
- 남은 일시 중지 시간 = `endsAt − now`. 0 이하이면 숫자를 내지 않는다(R-803).

규칙(P3):

- 멈춘 작업 시간을 이어 돌리는 모든 길("다시 시작", 돌아가기)은 먼저 하루 경계를 본다.
- 활성화가 저절로 끝내는 판정은 `holding`에서만 한다. `choosing`·`notes` 중에는 활성화가 돌아도 끝내지 않아 적던 글을 지킨다.
- 경계를 넘긴 제출은 위 표의 쓰기를 `StoreBatch` 하나로 한다. 할 일 값은 제출 때 새로 읽은 것을 쓴다. 입력 중 활성화가 붙인 `dueDecision`을 덮지 않기 위해서다.
- 쓰기가 실패할 때: 같은 하루의 제출은 아무것도 남기지 않고 남은 초부터 이어 돌며 다시 해 달라는 한 줄을 보인다(R-802). 경계를 넘긴 제출은 이어 돌 수 없으므로 입력 화면에 글을 남긴 채 다시 해 달라는 한 줄을 보인다.
- 일시 중지 두 줄의 글은 `notesDraft`와 따로 든다. `notesDraft`는 `session.run`이 바뀌면 지워져(`App/Sources/AppState.swift:108-110`) 쓰기 실패 뒤 이어 돌 때 글을 잃기 때문이다. 다음 "일시 중지"를 누르면 그 글이 칸에 남아 있고, 성공하거나 돌아가기로 닫으면 지운다.
- "다시 시작"의 쓰기 실패는 research R14다.
- 길이가 끝난 펼침은 멈춘 작업 시간이 기다릴 때와 초안이 돌아왔을 때만 `isPinnedOpen`으로 고정한다. "다시 시작"으로 이어 돌 때와 §4 끝내기에서 풀고, 돌아온 초안은 시작할 때 푼다(지금 규칙과 같다). 길이가 끝난 뒤 초안이 없는 화면(빈 상태, 이월 카드, 가용 시간 질문, 오늘 끝)은 고정하지 않고 활성화만 돌린다.
- 게이트가 묻거나 확인하는 동안에는 "일시 중지"를 누를 수 없다(P11). 숨길지 꺼 두고 이유를 보일지는 시안 M1에서 사람이 고른다. 일시 중지 중에는 `refreshGate`가 게이트를 열지 않고, 끝날 때 다시 판정한다.

## §3 남은 초, 경과 분, 쓴 시간 (R-802, R-805, R-833)

- 돈 초 = `quantumMin × 60 − remaining`. `pause`, `quit`, `day_end` 체크포인트의 경과 분은 `floor(돈 초 / 60)`이고 `0...quantumMin`으로 자른다.
- 이어 돌 때 끝 시각 = 누른 시각 + `remaining`, 시작 시각 = 끝 시각 − `quantumMin × 60`이다(research R13). 그 뒤 끝나는 체크포인트는 기존 식 그대로 멈춘 시간을 뺀 분이 된다.
- 멈춘 동안과 이어 돌 때 쓴 시간은 더하지도 빼지도 않는다.
- 돌려줄 초는 함수 하나에서 가른다(P4): 도는 중이면 `DayBudget.refundSeconds(endsAt:now:)`, 멈춘 채면 `floor(remaining)`, 시간 끝이면 0.

| 끝나는 길 | 돌려줄 초 | 체크포인트 | 로그 줄 |
|---|---|---|---|
| 이어 돈 뒤 완료·미루기·바꾸기 | `endsAt − now`(기존) | 기존 | 기존 |
| 이어 돈 뒤 긴급으로 끊김 | `endsAt − now` | `urgent` | `urgent` |
| 이어 돈 뒤 정상 종료 | `endsAt − now`(기존) | `quit`(기존) | 없음 |
| 멈춘 채 정상 종료 | `floor(remaining)` | `quit`, 빈 두 줄 | 없음 |
| 멈춘 채 하루 경계 | `floor(remaining)`을 `budgetDay` 기록에 | `day_end`, 빈 두 줄 | 없음 |
| 멈춘 채 설정 창에서 지움 | `floor(remaining)`을 `budgetDay` 기록에 | 없음 | 없음 |
| 도는 중 설정 창에서 지움(P4, spec 005 동작 변경) | `endsAt − now`를 `budgetDay` 기록에 | 없음 | 없음 |
| 멈춘 채 잠자기 | 없음(이어짐) | 없음 | 없음 |
| 비정상 종료 | 돌려받지 못함 | 없음 | 없음 |

`NotchSession.taskDropped`의 서명은 그대로 두고, 돌려줄 값은 위 함수로 따로 구한다. 순서는 `taskDropped`를 부르기 전에 값을 구하고, `pickIfEmpty`를 부르기 전에 쓴다. 그래야 돌려받은 시간이 모드 판정에 들어간다.

## §4 멈춘 채 하루 경계를 넘김 (R-806)

판정 자리는 §2 표다. 끝내기는 `SessionAssembly.activate` 안에 두지 않고 그 앞의 별도 단계로 한다. 앱과 시뮬레이터가 같은 순서를 쓴다.

**끝내기**(도는 중에서 멈춘 경우):

1. `NotchSession`의 끝내기 함수가 `SessionStep`을 만들고 커밋한다: 할 일을 대기로 돌리고 `day_end` 빈 체크포인트를 쓴다. 비어 있는 다음 줄은 첫 행동을 덮지 않는다.
2. 세션을 바꾼다: 타이머를 빈 상태로, `taskID`·`run`·`pause`를 nil로 둔다.
3. 저장한 남은 초를 `budgetDay` 기록에 돌려준다. `day_budget`은 기록 하나뿐이라 오늘 답을 쓰기 전에 끝나야 한다(research F13).
4. `SessionAssembly.activate`를 부른다: 반복 리셋 → 이월 판정 → 모드 → 고르기.

**초안 끝내기**(초안에서 멈춘 경우): `pause`를 nil로 두고 위 4를 부른다. 쓰기는 없고, 초안은 모드가 정한다.

실패할 때:

| 실패한 단계 | `holding`에서 끝낼 때 | 입력 중(`choosing`·`notes`)에 제출·돌아가기로 끝낼 때 |
|---|---|---|
| 1 커밋 | 세션을 그대로 두고 돌려주지 않는다. 다음 활성화가 다시 끝낸다. `day_end`는 한 줄만 남는다 | 입력 화면과 적은 글을 그대로 두고 다시 해 달라는 한 줄을 보인다. 사용자가 다시 누르면 다시 끝낸다. `day_end`는 한 줄만 남는다 |
| 3 돌려주기 | 로그 한 줄만 남기고 다시 쓰지 않는다(spec 005 data-model §9 끝). 세션은 이미 바뀌어 `day_end`가 겹치지 않는다 | 왼쪽과 같다 |
| 4 활성화 | 지금 활성화 실패와 같다. 끝내기는 다시 돌지 않는다 | 왼쪽과 같다 |

"다시 시작"과 돌아가기가 이 길로 끝나면 `resume` 줄을 남기지 않는다(R-815).

## §5 첫 행동과 판단 질의 (R-802, R-803)

- `pause` 체크포인트의 다음 줄이 비어 있지 않으면 첫 행동을 바꾼다(`takeNextNote` 그대로). 그 판단 질의는 일시 중지가 끝날 때 보낸다.
- 일시 중지 동안 질의 실행기는 새 질의를 꺼내지 않는다. 이미 나간 질의의 결과는 저장하고 화면을 바꾸지 않는다(research F11).
- 일시 중지가 끝나는 모든 길에서 `requestScores`를 부른다: "다시 시작", 돌아가기, 길이 끝, §4 끝내기, 설정 창에서 지워 풀릴 때. 활성화를 거치지 않는 길도 빠뜨리지 않는다.

## §6 노치 모드 (R-831)

`NotchMode`에 `.paused`를 더한다. 순서:

| 순서 | 조건 | 모드 | 고르기 |
|---|---|---|---|
| 1 | 앱 DB를 열 수 없음 | `.storageUnavailable` | 없음 |
| 2 | 도는 중(멈춤 제외) 또는 시간 끝 | `.session` | 없음 |
| 3 | 일시 중지 중(`.paused` 타이머 또는 일시 중지 인자) | `.paused` | 없음 |
| 4 | 카드에 오를 할 일이 있음 | `.carryCard` | 없음 |
| 5 | 오늘 기록이 없음 | `.askBudget` | 없음 |
| 6 | 오늘 끝 | `.dayEnd` | 없음 |
| 7 | 그 밖 | `.session` | 빈 상태면 고르기 |

- `.paused.clearsDraft`는 거짓이다. 초안에서 멈춘 일시 중지가 끝날 때 이 표로 다시 보고 7일 때만 같은 초안을 띄운다. 그 할 일이 대기가 아니면 스케줄러가 고른다.
- 일시 중지 중 빠른 입력은 저장만 하고 초안을 바꾸지 않는다. 모드가 `.paused`이면 `addedTask`를 부르지 않고, `addedTask` 자체도 멈춘 동안 세션을 그대로 돌려준다.
- 다시 띄운 초안의 `pickedBy`는 처음 떴을 때 값 그대로이고 스케줄러 메모리를 바꾸지 않는다.

## §7 자동 시작 (R-832)

`AutoStart`에 조건 하나를 더한다: `awaitsFirstInput`이면 시작하지 않는다. 값은 `AppState`가 `draftShownAt`·`lastInputAt`과 함께 메모리에 들고 `AutoStart`에 인자로 넘긴다.

- 참이 되는 때: 초안에서 멈춘 일시 중지가 길이가 끝나 돌아왔을 때, 앱을 다시 켠 뒤 첫 초안.
- 거짓이 되는 때: 칩, 버튼, 키 입력 함수에서만 끈다. `noteInput` 안에서 끄지 않는다.
- 끄지 않는 자리: 깨어남(`App/Sources/AppState.swift:526-530`), 기본 작업 시간 변경(`:934`), 자동 시작 설정 변경(`:979`), 판 클릭(`:1204`). 모두 `noteInput`을 부르지만 사용자가 그 초안에 답한 입력이 아니다.
- "다시 시작"을 눌러 끝낸 초안은 그 누름이 입력이라 참이 되지 않는다.
- 시험: 위 네 자리를 지난 뒤에도 시작 0건(SC-808). 앱 함수의 경로라 단위 3 `AppPauseTests`에 둔다.

## §8 긴급 입력 (R-811, R-812)

입력 값 `UrgentInput { title, chipMin, notes, extend }`.

순서(사용자 결정 2026-11-18(오케스트레이터 전달), research P9): 제목·칩 입력 → 두 줄(등록 또는 안 적기) → 제출 시각에 실제 남은 초로 판정 → 모자라면 늘리기 확인 → 시작. 칩을 고르는 단계에는 확인이 없다.

**남은 초**: 한 시각 `t`로 계산한다.

```text
돌려받을 초 = budgetDay == today ? max(0, floor(endsAt − t)) : 0   // 시간 끝이면 0
쓸 수 있는 초 = 오늘 기록의 remainingSeconds + 돌려받을 초
남은 분 = 쓸 수 있는 초 / 60 내림
```

- `remainingMinutes`(음수를 자름)는 쓰지 않는다. 오늘 기록이 없거나 "더 할래요" 뒤면 상한이 없다.
- 칩 처음 값: 설정 기본 작업 시간이고, 남은 분이 1 이상이고 더 짧으면 그 값이다. 남은 분이 0이면 기본 작업 시간 그대로다(P2).

**제출 판정**: 상한이 없거나 칩 ≤ 남은 분이면 바로 시작한다. 칩이 남은 분보다 길면 언제나 늘리기 확인을 보인다. 말없이 칩을 줄이거나 늘리지 않는다.

| 남은 분 | 확인 글자 | 수락 | 거절 |
|---|---|---|---|
| 1 이상 | 오늘 시간을 {칩 − 남은 분}분 늘려서 {칩}분 할까요? | "늘리고 시작": 동의한 숫자 그대로 늘리고 그 칩으로 시작 | "{남은 분}분만 할래요": 칩을 남은 분으로 줄여 바로 시작 |
| 0 | 오늘 남은 시간이 없어요. {칩}분 늘려서 할까요? | "늘리고 시작" | "돌아가기": 입력을 닫고 하던 일을 이어 감. 적은 두 줄은 버림. 끊을 할 일이 이미 시간 끝이면 시간 끝 화면으로 가며 두 줄을 그 화면 칸에 넘김(research R20) |

- 시작 전 화면의 `QuantumChip.extendNeeded`는 바꾸지 않고 긴급 전용 판정을 따로 둔다.
- 확인 줄이 떠 있는 동안에도 끊을 할 일의 시간이 흐른다. 확인 줄의 숫자는 1초마다 다시 계산해 보이고, 누르면 그 순간 화면에 보인 값(늘릴 분, 칩, 돌려줄 초)을 쓴다(research R22). 돌려줄 초도 화면 값을 써야 `used_s ≤ 가용 시간`이 지켜진다. 하루 경계를 넘긴 뒤는 아래 표의 예외다.
- 표의 행은 1초 재계산으로 바뀔 수 있다. 남은 분이 1에서 0으로 바뀌어 거절 버튼이 "N분만 할래요"에서 "돌아가기"로 바뀌면, 바뀐 직후 1초 동안 그 버튼의 누름과 Esc를 무시한다. 잘못 눌러 적은 두 줄을 잃지 않게 하기 위해서다.

확인 줄이 떠 있는 동안 생기는 일(research R26):

| 상황 | "늘리고 시작" | 거절 버튼 |
|---|---|---|
| 하루 경계를 넘겨 상한이 사라짐. 넘긴 순간 화면의 행과 N을 고정하고 재계산을 멈추며, 확인 줄은 누를 때까지 유지 | 늘리지 않고 칩 그대로 시작 | "N분만 할래요"는 보인 N분으로 시작, "돌아가기"는 입력을 닫음 |
| 끊을 할 일이 시간 끝이 됨 | 돌려주기 0초로 그대로 진행(계기 `urgent`, 경과 분은 고른 분) | "N분만 할래요"는 보인 N분으로 시작, "돌아가기"는 입력을 닫고 시간 끝 화면으로 가며 적은 두 줄을 그 화면 칸에 넘김 |

- 두 상황이 겹치면(하루 경계를 넘겼고 끊을 할 일도 시간 끝) 거절 버튼의 "돌아가기"는 시간 끝 행을 따른다.
- 하루 경계를 넘긴 뒤의 돌려주기는 누른 시각의 실제 남은 초를 `budgetDay` 기록에만 쓴다. 오늘 상한과 상관없는 값이라 고정하지 않는다.

키(확인 줄):

| 키 | 동작 |
|---|---|
| Enter | 키 반복은 언제나 무시한다. 확인 줄이 뜬 직후 0.5초 동안의 Enter도 무시하고(두 줄 제출의 Enter가 이어져 숫자를 읽기 전에 늘어나지 않게), 그 뒤의 새 Enter만 "늘리고 시작"이다 |
| Esc | 화면에 보이는 행으로 판정한다. 0분 행이면 "돌아가기"이고, 1분 이상 행이면 두 줄 입력으로 돌아가 적은 글을 유지한다. 1→0 전환 직후 1초 동안은 무시한다 |

**끊을 할 일이 사라질 때**: 제목·칩·두 줄·확인 줄 어느 단계든 끊을 할 일의 `taskID`가 바뀌거나 `run`이 없어지면(설정 창에서 지움 등) 입력을 닫고 긴급 쓰기를 하지 않는다. 돌려주기는 지울 때(§3) 한 번만 한다.

쓰기 순서:

1. 제목 규칙(spec 002 R-101)과 칩 범위를 본다.
2. 위 제출 판정을 지난다.
3. 한 번에 쓴다(P7): `TaskRepository`의 긴급 전용 메서드가 한 트랜잭션으로 새 할 일(진행 중, 마감이 없으면 오늘), 끊긴 할 일(대기, 미룬 횟수 그대로, 첫 행동), 체크포인트 `urgent`, 로그 줄 `urgent`를 쓰고 새 할 일을 돌려준다. `applyCarryJudgment` 무늬다. 끊을 할 일은 제출 때 새로 읽은 값을 쓴다. 결과는 둘로 나눈다.
   - 거부(끊을 할 일이 진행 중이 아님): 메서드가 쓰기 실패와 다른 오류로 알리고 아무것도 쓰지 않는다. 입력을 닫고 다시 해 달라는 줄을 보이지 않는다. 긴급 쓰기는 0건이고 돌려주기는 그 할 일을 끝낸 길이 한 번만 한다.
   - 쓰기 실패: 지금 할 일은 그대로 돌고, 입력과 적은 두 줄을 남긴 채 다시 해 달라는 한 줄을 보인다.
4. `day_budget`을 한 번 쓴다: 동의한 늘린 분(`extended(by:)`) + 끊긴 할 일 돌려주기 + 긴급 칩 더하기. 쓰기가 실패하면 로그 한 줄만 남긴다(spec 005 data-model §9 끝).
5. `last_start_day`를 쓴다.
6. 세션을 긴급 할 일로 바꾼다. `pickedBy = urgent_pin_v1`.

- 끊긴 할 일의 `budgetDay`가 오늘과 다르면 돌려받을 분을 상한에 더하지 않고, 돌려주기는 그 하루 기록에만 한다. 오늘 기록이 없으면 긴급 칩은 어느 하루에도 더하지 않는다.
- 입력 중 시간 끝이 와도 입력을 닫지 않는다. 지금은 두 줄 입력이 도는 중이 아니면 닫히므로(research F10) 긴급 입력은 따로 다룬다. 체크포인트 경과 분은 고른 분이다.

## §9 긴급 고정과 복귀 제안 (R-813, R-814)

`NotchSession`에 칸 `urgent: UrgentState?`를 더한다(P5). init 인자에 기본값을 두지 않아 세션을 새로 만드는 자리(`NotchSession.swift:118·306·437`)를 컴파일러가 잡는다.

```swift
struct UrgentState: Equatable, Sendable {
    var pinnedTaskID: TaskID?   // 긴급 고정된 할 일
    var returnTaskID: TaskID?   // 복귀 제안을 기다리는 끊긴 할 일
}
```

고정 값은 `PriorityOrder.order`와 `PickInput`에 입력으로 넘긴다. `SchedulerMemory`는 바꾸지 않는다.

| 사건 | 고정 | 끊긴 할 일 |
|---|---|---|
| 긴급 시작 | 새 긴급 할 일 | 지금 끊은 할 일(앞 값을 덮음, 한 단계만) |
| 긴급 할 일 완료 | 풀림 | 남김(아래 띄움에서 씀) |
| 긴급 할 일 미루기·바꾸기·지우기 | 풀림 | 지움 |
| 일시 중지, 다시 시작, "N분 더" | 그대로 | 그대로 |
| 복귀 제안을 띄움 | 그대로(없음) | 지움 |
| 고정된 할 일에 이월 답 `today` | 그대로 | 그대로 |
| 고정된 할 일에 이월 답 `move` | 풀림(미루기와 같음) | 지움 |
| 고정된 할 일에 이월 답 `drop` | 풀림(지우기와 같음) | 지움 |
| 앱 재시작 | 풀림 | 지움 |

- 고정 풀기: 고정된 할 일이 대기도 아니고 노치에서 도는 할 일도 아니면(완료, 버림) 고정을 푼다.
- 고르기: 고정된 할 일이 후보이면 워밍업과 가중 순환보다 먼저 고른다. 바꾸기·미루기 직후 빼는 규칙(R-408)은 그대로다. 이름은 `urgent_pin_v1`이다. 이 고르기는 몫과 최근 고르기를 바꾸지 않는다(research R23).
- 후보 순서: `PriorityOrder.order`가 고정된 할 일을 맨 앞에 둔다. 할 일 탭 순위와 "다음"도 이 순서다.
- 띄움: 모드 판정(§6)이 7이고 고정된 할 일이 없고(`pinnedTaskID == nil`) 끊긴 할 일이 대기이면 고르기 대신 그 할 일을 초안으로 띄운다. 이름은 `urgent_return_v1`이고 스케줄러 메모리(몫, 최근 고르기)를 바꾸지 않는다. 고정된 할 일이 남아 있으면 끊긴 할 일을 남긴 채 고정된 할 일을 먼저 고른다. 끊긴 할 일이 대기가 아니면 지우고 스케줄러가 고른다. 오늘 끝이나 이월 카드가 먼저이면 7이 될 때까지 남겨 둔다("더 할래요" 뒤 포함).
- 앱에서 고정이 고르기에 쓰이는 길은 멈춘 긴급 할 일이 하루 경계로 대기가 된 경우뿐이다(research F12). 시험은 이 길로 한다.

순서 시험(단위 1·2 필수):

- 끝내기 실패 주입: 커밋이 실패하면 세션과 쓴 시간이 그대로이고 다시 끝낸 뒤 `day_end`가 한 줄이다. 입력 중이면 적은 글도 남는다. 돌려주기가 실패하면 `day_end` 한 줄과 로그 한 줄이 남는다(§4).
- A를 끊은 긴급 U를 멈춘 채 하루 경계를 넘기고 이월 카드에 답하면 A가 아니라 U가 뜬다(§9).
- U 완료 → A 복귀 제안 → A 시작 → A 미루기 뒤 A가 바로 다시 뜨지 않는다(§9, spec 005 R-408).
- 초안 멈춤의 같은 하루·넘김 길마다(돌아가기, 길이 고름, "다시 시작", 활성화), 초안 멈춤 중 지운 뒤 새 초안을 고르지 않음(§2).
- 긴급 제출(§8): 칩 ≤ 남은 분이면 확인 없이 시작, 칩이 더 길면 언제나 확인, 수락하면 동의한 숫자 그대로 시작하고 `day_budget` 쓰기가 한 번, "N분만 할래요"는 남은 분으로 시작, 0분의 "돌아가기"는 기록 0건이고 두 줄을 버림, 확인이 떠 있는 동안 숫자가 다시 계산되고 누른 순간의 값을 씀.
- 고정된 할 일에 이월 답 셋을 보낸 뒤 고정과 끊긴 할 일이 §9 표대로다.
- 긴급 입력의 각 단계에서 끊을 할 일을 지우면 입력이 닫히고 긴급 쓰기가 0건이며, 돌려주기는 한 번이고, 버린 할 일이 대기로 되살아나지 않는다. 제출 때 진행 중이 아니면 거부로 입력을 닫고 다시 요청하지 않으며, 쓰기 실패만 입력과 두 줄을 남기고 다시 요청한다(§8).
- 확인 줄 중 하루 경계: 버튼 셋의 결과, 돌려주기가 `budgetDay` 기록에만 감, 상한이 사라져도 확인 줄이 유지됨, 넘긴 순간 행과 N이 고정되어 재계산이 멈춤, 고정된 0분 행의 Esc는 "돌아가기"이고 고정된 1분 이상 행의 Esc는 두 줄로 돌아감(§8).
- 확인 줄 중 남은 분 1→0 전환(단위 5 `AppUrgentTests`도): 거절 버튼이 "돌아가기"로 바뀐 직후 1초 동안의 누름과 Esc는 무시됨(§8).
- 확인 줄 중 시간 끝: "늘리고 시작"은 돌려주기 0초, 계기 `urgent`, 경과 분은 고른 분이고, "돌아가기"는 시간 끝 화면의 칸에 두 줄을 넘김(§8).
- 확인 줄의 키(단위 5 `AppUrgentTests`): 키 반복은 언제나 무시, 뜬 직후 0.5초의 Enter 무시, 그 뒤의 새 Enter만 "늘리고 시작", Esc는 보이는 행이 0분이면 "돌아가기"이고 1분 이상이면 두 줄로 돌아가 글을 유지함(§8).
- 일시 중지가 끝나는 길마다 `requestScores`가 불린다(§5, 단위 3 `AppPauseTests`).

저장 계약 시험(P7, 메모리·GRDB 둘 다): 긴급 전용 메서드에 실패를 주입한 뒤, 그리고 진행 중이 아닌 할 일을 넘겨 거부된 뒤 새 할 일, 끊긴 할 일 갱신, 체크포인트, 로그가 모두 0건이다.
