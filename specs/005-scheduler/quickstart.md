# Quickstart: 스케줄러 확인 (spec 005)

결과는 PASS / FAIL / SKIP / NOT_RUN으로만 적는다. 실행하지 않은 것은 PASS로 적지 않는다. 가짜 할 일만 쓴다. 규칙은 [data-model.md](data-model.md), 화면 글자는 확정 시안 `~/Dev/ai-platform/projects/moka/design/005-mockup.html`(확정 전)이다. 에이전트는 실제 앱 DB, Keychain, 실제 판단 API를 열지 않는다(R-431).

## 1. 핵심 로직 (자동, 리눅스 CI `core-test`)

```
swift test
```

기대:

- 고르기(`SchedulerPickTests`): 후보 A 1.5·B 0.9·C 0.6·D 0.3에서 100번 고르면 A·B·C가 50·30·20(SC-401의 2 이내), D 0번. 바꾸기·미루기로 방금 할 일을 건너뛰어도 D 0번(창은 앞 셋을 먼저 정함). 같은 입력 두 번이면 같은 순서. 점수 없는 할 일이 섞이면 순위 몫 5:3:2. 후보 둘이면 앞 둘만, 하나면 그 할 일. priority 0 후보도 창 안이면 0번이 아님. 바꾸기·미루기 직후 방금 할 일은 빠짐(후보 하나면 예외). 순수 함수에 "직전 두 고르기 A"를 넣으면 A가 아님(R-404). "현재 A, 남은 20분, 작업 25분"이면 A(R-405, 연속 상한보다 앞섬). 다 하는 데 걸릴 시간이 없으면 마무리 규칙 없음. 워밍업: concrete 0.8 이상·30분 이하 가운데 1위, 없으면 가중 순환, `warmup_v1` 이름(R-406).
- aging(`ScoreRulesTests`): 미루기 1번이면 aging 1, "오늘 할래요" 1번이면 0.5, avoiding 임계값 이상이면 1.5배(R-402). 판단 입력 해시는 `carryCount`와 상관없음.
- 후보(`PriorityOrderTests`): 이월 답 대기는 순서·순위·"다른 할 일"에서 빠짐(R-401, R-413).
- 이월 판정(`CarryJudgmentTests`, 주입한 시계·달력): spec US2 시나리오 1·5·6·6a·6b·6d·9, 처음 판정은 바로 앞 하루 시작부터, 같은 하루 두 번째는 돌지 않음, 같은 초 경계 포함, 판정 쓰기 실패 뒤 재판정에 `revertedIDs`가 들어감, 이미 대기인 표시는 지우지 않음, 이월 답 로그 줄은 손댄 것으로 세지 않음, 반복 할 일 제외, 05:59와 06:00 경계, 며칠 건너뜀.
- 이월 답(`CarryAnswerTests`): 답 셋의 할 일 갱신과 로그 한 줄(`carry_card_v1`, 판단 칸 R-212), 날짜는 내일부터, 진행 중 완료가 표시를 지움(R-415~R-417).
- 가용 시간(`DayBudgetTests`): 남은 분 내림, 칩 상한(시작 전·시간 끝), 남은 분보다 긴 프리셋 꺼짐과 직접 입력 오류, 1분 미만이면 오늘 끝, "더 할래요" 뒤 상한 없음, 쓴 시간 셈(시작 때 고른 분을 더하고 일찍 끝나면 남은 초를 돌려줌), 하루가 바뀌면 어제 기록 무시(시작 전 칩과 오늘 끝 기준), 하루 경계를 넘긴 작업 시간의 "N분 더"는 시작한 하루(`budgetDay`) 기록으로 칩 상한·더하기·돌려주기를 하고 그 기록의 남은 분이 1 미만이면 꺼짐·기록이 없거나 "더 할래요"면 상한 없음(R-409, R-419~R-422).
- 모드(`NotchModeTests`): data-model §12 표 여섯 줄, 카드·질문·오늘 끝에서 초안 비움, 도는 중이면 판정 뒤에도 그대로(R-417).
- 세션(`NotchSessionSchedulerTests`): 가용 2시간에서 주입한 시계로 작업 시간을 이어 돌려 "더 할래요" 전 쓴 시간 120분 이하와 시작 칩이 남은 분 이하, 쓴 시간이 120분에 닿으면 오늘 끝, 일찍 끝낸 작업 시간 뒤 돌려주기가 모드 판정보다 먼저, 시간 끝과 겹친 미루기 뒤 고르기 0번과 계기 `day_end`(SC-405).
- 저장(`MokaStoreTests`): 마이그레이션 이름 목록 끝 `v4_tasks_carry`, 스냅샷 일치, v3 DB 사본 업그레이드 뒤 기존 행이 0·거짓, 판정 쓰기를 실패시키면 표시와 판정 시각이 둘 다 없음(SC-406).
- 시뮬레이터(`SimGoldenTests`, `SimScenarioTests`): 새 golden(이월, 가용 시간, 오늘 끝과 "더 할래요", 워밍업, 하루 경계 진행 중), 새 오류 픽스처, 기존 storage golden은 바뀐 줄 표대로, spec 001 golden 바이트 그대로.
- 실제 판단 호출 0번(SC-410): 시험 번들이 `HTTPDecisionProvider`를 컴파일하지 않음(기존 시험 그대로).

## 2. 튜닝 계약 (자동, CI `tuning-test`)

```
cd tuning && python3 -m pytest
```

기대: tasks 두 열과 기본값·CHECK, `carry_*`·`carry_card_v1` 줄이 들어감, 기존 시험 그대로.

## 3. 시뮬레이터 직접 실행 (자동)

```
swift run moka-sim run Tests/MokaCoreTests/Fixtures/sim/storage-005-carry.json
```

기대: golden `storage-005-carry.expected.jsonl`과 같은 바이트, 종료 코드 0. 출력에 할 일 제목이 없음(ASCII만).

## 4. 앱 빌드와 앱 시험 (로컬 macOS, CI `app-build`)

```
xcodegen generate && xcodebuild build -scheme Moka -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO
xcodegen generate && xcodebuild test -scheme Moka -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO -only-testing:MokaAppTests
```

기대(단위별):

- 단위 2: 키 없음에서 노치가 마감일 순 앞 셋을 번갈아 띄움, 하루 첫 고르기가 워밍업, "다음" 표시가 다음 고르기 결과, 버튼 줄의 `scheduler_choice`, 앱 재시작 뒤 같은 하루면 워밍업이 다시 걸리지 않음.
- 단위 3: 주입한 시계로 하루를 넘겨 활성화하면 이월 카드, 답 셋, 답하기 전 고르기·초안·"다른 할 일"·순위에 나온 이월 대상 0건, 하루 경계에 도는 할 일의 미루기·완료·앱 재시작 흐름, 카드 없이 대기로 돌아온 건수 0(SC-403).
- 단위 4: 질문 전 고르기 없음, 답 뒤 고르기, 칩 상한, 오늘 끝, "더 할래요", 같은 하루 재시작에 다시 묻지 않음, 시간 끝 겹침에서 "N분 더" 꺼짐과 Enter 막음(SC-405, SC-406).
- 단위 5: `HelpContentTests`·`GuideTests`가 확정 시안 13번 글자와 같음, 도움말 3번 문장 수 2~5.
- 단위 6: 자동 시작이 3초 뒤 한 번, 입력·게이트·카드·질문·오늘 끝에서 시작하지 않음, "내일" 표시 계산.

## 5. 화면 스냅샷 (로컬, CI `app-snapshots` 경고만)

data-model §19 이름 전부(라이트·다크). 바뀌는 기존 그림(할 일 탭 순위, 기본 탭, 시간 끝 화면은 바뀌지 않아야 함)을 PR에 적는다. 확정 시안과 나란히 보는 비교 페이지를 `~/Dev/ai-platform/projects/moka/design/pr-<번호>/index.html`에 만든다(ADR-0009).

## 6. 사람 확인 (단위 순서대로)

확인 순서를 적기 전에 그 상태를 지금 빌드에서 만들 수 있는지 먼저 본다. 모든 확인은 그 단위 PR 브랜치의 확인용 빌드로 한다. 하루 경계는 실제로 기다리지 않고 설정 창 "하루 시작 시각"을 지금 시각 바로 뒤로 바꿔 만든다(spec 002 R-114의 설정).

| # | 단위 | 확인 | 상태를 만드는 법 | 대응 |
|---|---|---|---|---|
| 6-1 | 2 | 지금 쓰는 앱을 확인용 빌드로 바꿔 켜면 할 일 목록과 미룬 횟수가 그대로이고, 노치를 펼쳤다 바꾸기를 몇 번 누르면 앞 세 할 일이 번갈아 뜬다 | 기존 사용 중인 앱 위에 확인용 빌드를 켬(앱 DB를 지우지 않음) | 위험 13, R-403 |
| 6-2 | 3 | 가짜 할 일 둘을 만들고 하나를 미룬 뒤, 하루 시작 시각을 1분 뒤로 바꾸고 1분 지나 노치를 펼치면 미룬 할 일만 이월 카드에 뜬다. "날짜 바꿀래요"로 달력을 열면 오늘과 지난 날은 누를 수 없다. "오늘 할래요"를 누르면 카드가 닫히고 다음 화면이 뜬다 | 설정 창 기본 탭 하루 시작 시각. 확인 뒤 06:00으로 되돌림 | US2-1~4, R-414 |
| 6-3 | 3 | 6-2에서 카드가 떠 있을 때 앱을 종료했다 다시 켜면 같은 할 일부터 카드가 뜬다 | 6-2 상태 | US2-8 |
| 6-4 | 4 | 카드를 마친 뒤 "오늘 몇 시간 할까요?"에서 1시간을 고른다. 칩에서 45분을 골라 시작하고 끝까지 둔 뒤 완료를 누르면, 다음 할 일의 칩이 15분이고 25분·45분·60분은 흐리다. "직접…"에 30을 적으면 오늘 남은 시간이 15분이라는 빨간 줄이 보이고 시작이 꺼진다 | 6-2에 이어서. 실제 타이머 45분이 든다 | US3-1~3, R-421 |
| 6-5 | 4 | 6-4에서 15분으로 시작해 끝까지 두면 시간 끝 화면의 "N분 더"가 꺼지고 이유 한 줄이 보인다. 미루기를 누르면 "오늘 끝"이 보이고, 앱을 종료했다 다시 켜도 "오늘 끝"이다. "더 할래요"를 누르면 할 일이 뜬다 | 6-4 상태. 실제 타이머 15분이 든다 | US3-4·4a·4b·5·6 |
| 6-6 | 5 | 설정 창 도움말 3·6번과 기본 탭 키 칸 문구가 확정 시안 13번과 같다 | 확인용 빌드 | R-434 |

6-4·6-5는 가용 시간 선택지가 1시간부터라 상태를 만드는 데 실제 타이머 1시간이 든다. 확인할 시간이 없으면 NOT_RUN으로 적고 앱 시험(4)의 결과만 보고한다.
