# Research: 판단 결과 화면 연결 (spec 004)

결정마다 Decision, Rationale, Alternatives를 적는다. 토론 기록은 로컬 `.audit/debate/`에 있고 커밋하지 않는다. "사람 확인 대기"는 무인 실행에서 정해 사람이 PR에서 확인할 항목이다.

## R1. 범위 (작업 지시, spec 003 Non-Goals)

- **Decision**: spec 003이 미룬 넷만 담는다. FR-04 이유 줄, FR-13 구체화 게이트, FR-16·FR-21 온보딩 키 단계, 노치·할 일 탭 키 확인 표시다. 공급자는 TypeSafe Jev 하나 그대로이고 스키마는 바꾸지 않는다.
- **Rationale**: 마일스톤 3 완료 조건 가운데 화면에 닿는 것만 남았다. spec 003 데이터(`scores`, `TaskScore`, `ScoreRules`, `ranks`, `keyNeedsCheck`)로 모두 만들 수 있다.
- **Alternatives**: FR-06 "다음 2개"까지 담기(마일스톤 4 스케줄러와 함께 정하는 편이 맞음), 게이트 입력을 행동 로그에 남기기(새 사용자 행동 값은 승인 항목).

## R2. 게이트를 넘길 수 있다 (spec Q1, R-307, debate 3:0, 무인 실행 2026-11-10, 사람 확인 대기)

- **Decision**: 게이트는 시작 전 화면의 시간 고르기 위에 뜨고 "지금은 넘기기"를 함께 보인다. 넘기기는 통과다. 입력 칸이 열린 동안 Enter는 제출이고 시작 버튼의 Enter 단축키는 뗀다. 다른 할 일, 새 할 일, 시작 버튼 누르기는 켜 둔다. 넘기기는 로그에 남기지 않는다.
- **Rationale**: PRD FR-13에 넘기기를 막는 문장이 없다. 강제 입력은 PRD의 건너뛰기 패턴(FR-07 두 줄, FR-21 키)과 어긋난다. 빠져나가려고 아무 줄이나 세 번 적으면 첫 행동과 판단 입력이 더러워진다. 입력 칸을 열면 시작 단축키를 떼는 선례가 이미 있다(`App/Sources/Views/ExpandedView.swift:143`).
- **Alternatives**: 넘기기 없이 통과까지 강제(1라운드 가이드 자리), 안내만 하고 시작하면 닫힘(1라운드 실행 자리, 입력 칸 Enter가 제출과 시작으로 겹침).
- 표결: 1라운드 1:1:1, 2라운드 3:0. 소수 의견 없음. 게이트를 꼭 적게 하는 장치로 원하면 넘기기 금지와 "첫 행동이 있으면 게이트 없음" 짝이 맞다는 조건만 남았다.

## R3. 게이트 기록은 메모리에만 (spec Q2, R-309, debate 3:0, 무인 실행 2026-11-10, 사람 확인 대기)

- **Decision**: 할 일별 제출 횟수, 기다리는 해시, 통과 여부를 AppState 메모리에만 둔다. 앱을 다시 켜면 사라진다.
- **Rationale**: 스키마와 설정 키를 늘리지 않는다(작업 지시). 키 확인 필요도 메모리 값이라는 선례가 있다. 넘기기로 통과한 할 일은 첫 행동이 남지 않으므로 "첫 행동이 있으면 열지 않음" 규칙으로는 기억할 수 없다. 다시 켠 뒤 열려도 넘기기 한 번으로 닫힌다.
- **Alternatives**: 설정 표에 할 일별 통과 해시(사용자 DB에 남아 되돌리기 어려움), 첫 행동이 있으면 게이트 없음(체크포인트 첫 행동도 판정 대상이라는 PRD와 어긋남).

## R4. 접힌 노치에는 키 확인 표시 없음 (spec Q3, R-316, debate 3:0, 무인 실행 2026-11-10, 사람 확인 대기)

- **Decision**: 펼친 화면 한 줄만 둔다.
- **Rationale**: PRD FR-06 접힌 화면은 제목과 남은 시간만 보인다. 접힌 화면 상태를 늘리면 spec 001 스냅샷과 시안을 다시 봐야 한다.
- **Alternatives**: 접힌 노치에 작은 표시, 키 확인 필요가 된 직후 몇 초만 표시.

## R5. 재판정은 spec 003 다시 묻기 규칙으로 (메인 세션 판단, 코드 확인)

- **Decision**: 새 질의 경로를 두지 않는다. 게이트는 첫 행동을 `StoreBatch(updatedTasks:)`로 쓰고 할 일을 다시 읽는다. 판정은 그 할 일의 판단 결과 가운데 `stateHash`가 지금 판단 입력 해시와 같은 것으로만 한다. 지금 해시로 보낸 질의가 실패했거나 물을 수 없게 되면 통과다.
- **Rationale**:
  - `JudgmentState.build`가 `first_action`을 판단 입력에 넣는다(`Sources/MokaCore/Decision/JudgmentState.swift:42,54`). 첫 행동이 바뀌면 해시가 바뀐다.
  - `reloadTasks()`가 `requestScores()`를 부른다(`App/Sources/AppState.swift:1019`). 해시가 바뀐 할 일은 `ScoringPlan.needsQuery` 대상이다.
  - `ScoreRules.usable`은 해시를 보지 않는다(`Sources/MokaCore/Decision/ScoreRules.swift:102`). 제출 직후에는 낡은 concrete가 남아 있으므로 해시 비교 없이 판정하면 곧바로 다시 실패로 본다.
  - 실패한 질의는 같은 해시로 다음 활성화까지 다시 보내지 않는다(spec 003 data-model §6). 기다리면 게이트가 오래 열린다.
- **Alternatives**: concrete 하나만 묻는 새 경로(공급자 경계와 질문 파일 계약이 바뀌고 판단 결과 한 벌 원칙이 깨짐), 게이트 할 일을 질의 줄 앞으로 당기기(spec 003 `needsQuery` 순서 규칙 변경, spec 위험 2).

## R6. 이유 줄 표기 (메인 세션 가정, 시안에서 확정)

- **Decision**: 이유 줄은 MokaCore가 글자를 만든다. 초안 표기는 "D-3 · 손해 꽤 · 미룬 2번"이다. 오늘 마감은 "D-day", 지난 마감은 "D+2", 마감 없음은 "마감 없음"이다. 손해는 impact에 (옵션 수 빼기 1)을 곱해 반올림한 번호의 질문 파일 impact 옵션 말로 고른다(지금 0.25 미만 "조금", 0.75 이상 "아주").
- **Rationale**: PRD FR-04가 "D-n"을 쓴다. 손해 말을 질문 파일에서 읽으면 옵션을 바꿀 때 화면이 따라간다. 반올림은 score 답이 옵션 번호의 확률 가중 평균이라는 spec 003 정의와 맞는다.
- **Alternatives**: 해요체 문장("마감까지 3일 남았어요", 노치 폭 340pt에 세 칸이 들어가지 않음), 손해를 숫자로(spec 003 순위 칸에서 사용자가 소수 숫자를 어색하다고 함).

## R7. 온보딩 키 단계 (메인 세션 가정)

- **Decision**: 단계는 키, 일정, 기본값 순서의 셋이다. 키는 키 단계 "다음"에서 spec 003 `saveKey`로 바로 저장한다. 실패 문구는 spec 003 `keyActionFailure`를 함께 쓴다. 발급 링크 주소는 앱 상수 한 곳에 두고 사람이 시안 확정 때 공식 문서에서 정한다.
- **Rationale**: PRD FR-21 순서다. Keychain은 앱 DB와 다른 저장소라 "시작하기"에서 한꺼번에 되돌릴 수 없다. 설정 창 키 칸과 같은 동작을 쓰면 시험과 문구가 하나다.
- **Alternatives**: "시작하기"에서 함께 저장(키 실패가 온보딩 끝내기 실패로 묶여 온보딩이 다시 나옴), 일정 뒤에 키 단계(PRD 순서와 다름).

## R8. 노치에서 설정 창 기본 탭 열기 (메인 세션 가정)

- **Decision**: AppState에 메모리 요청 값 하나(`settingsTabRequest`)를 두고, 노치 키 확인 한 줄의 동작이 그 값을 기본 탭으로 둔 뒤 기존 "설정…" 열기(`OpenSettingsButton`의 순서)를 부른다. `SettingsView`는 나타날 때와 값이 바뀔 때 탭을 바꾸고 값을 비운다. 할 일 탭의 한 줄은 같은 창 안이라 탭만 바꾼다.
- **Rationale**: `SettingsView`의 탭은 지역 `@State`다(`App/Sources/Settings/SettingsView.swift:17`). 새 창 종류나 의존성이 필요 없다.
- **Alternatives**: 탭을 AppState로 옮기기(설정 창 상태가 앱 상태와 섞임), 키 칸을 노치에 두기(노치 폭과 Keychain 확인 창).

## R9. 기존 스냅샷을 바꾸지 않는다 (메인 세션 가정)

- **Decision**: `ExpandedView`, `TaskListTabView`, `OnboardingView`의 새 인자는 기본값이 없음(`nil`, `false`)이다. 기존 스냅샷 호출은 그대로 두고 새 상태는 새 시험으로 찍는다. 온보딩도 키 단계 입력이 없으면 지금처럼 두 단계라 기존 참조 이미지가 바뀌지 않는다.
- **Rationale**: 헌법 II(테스트 약화 금지)와 spec SC-310. 바뀌는 참조 이미지를 최소로 한다.

## R10. 시작 버튼으로 시작하면 게이트를 닫는다 (메인 세션 가정)

- **Decision**: 게이트가 열린 채 시작 버튼을 누르면 게이트를 닫고 통과로 보지 않는다. 그 할 일이 다음에 시작 전으로 뜨면 남은 횟수로 다시 연다.
- **Rationale**: R-306은 도는 중에는 열지 않는다. 넘기기와 시작을 구분해야 넘기기가 "이번 앱 실행 동안 묻지 않기"라는 뜻을 가진다.
- **Alternatives**: 시작도 통과로 보기(넘기기 버튼이 필요 없어짐), 게이트가 열린 동안 시작 버튼을 끄기(R2에서 기각).
