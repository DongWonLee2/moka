## 용어

spec 001~006 용어(노치 할 일, 이유 줄, 구체화 게이트, 첫 행동, 판단 모델, 키, 키 확인 필요, 보내는 곳, 고른 공급자, 온보딩)를 그대로 쓴다. 이 spec에서 새로 쓰는 말은 다음과 같다.

- **도움말 탭**: 설정 창의 넷째 탭. 기능마다 짧은 설명을 목차로 보인다. 읽기만 하고 아무것도 저장하지 않는다.
- **도움말 항목**: 도움말 탭 목차의 한 줄과 그 아래 설명. 여덟 개다(R-703).
- **안내 장**: 온보딩 안에서 기능 하나를 그림 하나와 짧은 글로 보여 주는 한 장. 노치, 순위, 첫 행동 칸 세 장이다. 값을 받지 않는다.
- **설정 단계**: 지금 온보딩의 값을 받는 단계(키, 일정, 기본값). 안내 장과 구분하려고 쓴다.
- **안내 다시 보기**: 도움말 탭 맨 위 버튼. 누르면 설정 창 위 시트로 안내 장 셋을 다시 보인다(R-713).
- **인용 문구**: 도움말 글이나 안내 장 글 안에서 실제 화면 글자를 따옴표로 옮긴 부분. 예: "지금은 넘기기".

## Goals

- 사용자가 설정 창 도움말 탭 한 곳에서 노치, 할 일·일정, 순위, 이유 줄, 첫 행동 칸, 판단 모델과 키, 보내는 곳, 단축 동작을 언제든 찾아 읽는다.
- 처음 켠 사용자가 온보딩 맨 앞에서 노치, 순위, 첫 행동 칸을 한 장씩 보고 설정 단계로 간다.
- 이미 쓰는 사용자도 도움말 탭에서 안내 장을 다시 본다.
- 도움말과 안내 장의 인용 문구가 실제 화면 글자와 늘 같다. 화면 글자가 바뀌면 시험이 알려 준다.
- 스키마, 공개 계약(DecisionProvider, `questions.json`, `moka-sim` 시나리오 형식), 의존성, CI, 설정 키는 바꾸거나 더하지 않는다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 설정 창 도움말 탭에서 기능 설명을 찾아 읽는다 (Priority: P1)

사용자는 메뉴 막대의 "설정…"이나 노치 우클릭 메뉴로 설정 창을 열고 "도움말" 탭을 고른다. 목차에서 궁금한 항목(예: 이유 줄)을 누르면 그 아래 설명이 펼쳐진다. 설명은 화면에서 본 글자("D-3 · 중요도 보통 · 미룬 2번")를 그대로 인용해, 화면과 설명을 맞춰 볼 수 있다.

**Why this priority**: 사용자 결정 (1)이다. 처음 실행이 아니어도 늘 쓸 수 있고, 지금 쓰는 작성자 1인이 바로 혜택을 본다. 이 이야기 하나만 있어도 Issue #113의 "언제든 다시 본다"를 채운다.

**Independent Test**: 설정 창을 도움말 탭으로 열어 목차 여덟 항목과 각 항목 펼침을 스냅샷으로 찍는다(라이트·다크). 인용 문구가 화면 문자열 상수와 같은지 단위 시험으로 비교한다.

**Acceptance Scenarios**:

1. **Given** 설정 창이 열려 있다, **When** 탭 줄을 본다, **Then** "기본", "할 일", "일정", "도움말" 네 탭이 이 순서로 보인다.
2. **Given** 도움말 탭을 골랐다, **When** 탭을 본다, **Then** 맨 위에 설명 "노치, 순위, 첫 행동 칸 안내를 한 장씩 다시 볼 수 있어요."와 "안내 다시 보기" 버튼이 있고, 그 아래 목차 여덟 항목(R-703)이 모두 접힌 채 보인다.
3. **Given** 목차가 보인다, **When** "이유 줄"을 누른다, **Then** 그 항목 설명이 펼쳐지고 다른 항목은 그대로다. 한 번 더 누르면 접힌다.
4. **Given** "이유 줄"이 펼쳐져 있다, **When** "첫 행동 칸"을 누른다, **Then** 두 항목이 함께 펼쳐져 있다. (debate 3:0, 사용자 위임 2026-11-12)
5. **Given** 이유 줄 설명이 펼쳐졌다, **When** 글을 읽는다, **Then** 예시 "D-3 · 중요도 보통 · 미룬 2번"과 D-day, D+n의 뜻, 판단 결과가 없으면 중요도 칸이 빠진다는 것이 보인다.
6. **Given** 항목 둘을 펼친 채 "기본" 탭으로 갔다, **When** "도움말" 탭으로 돌아온다, **Then** 두 항목이 펼친 채 그대로다. 펼침은 저장하지 않는다(R-707). (debate 3:0, 사용자 위임 2026-11-12)
7. **Given** 앱 DB를 열 수 없다(spec 002 R-119), **When** 도움말 탭을 연다, **Then** 도움말은 그대로 보인다. 도움말은 DB를 읽지 않는다.

### User Story 2 - 처음 켤 때 노치, 순위, 첫 행동 칸을 한 장씩 본다 (Priority: P1)

처음 앱을 켠 사용자는 "Moka 시작하기" 창 맨 앞에서 안내 장 세 장을 넘기며 노치가 어떻게 펼쳐지는지, 노치가 무엇을 먼저 띄우는지, 막연한 할 일에 노치가 무엇을 묻는지 본다. 이어서 지금의 설정 단계(키, 일정, 기본값)를 마치고 "시작하기"를 누른다. 단계 표시는 한 줄로 1/6부터 6/6까지다.

**Why this priority**: 사용자 결정 (2)이다. 새 사용자가 첫 화면에서 게이트를 처음 보고 놀라지 않게 한다.

**Independent Test**: 가짜 설정 저장소(온보딩 안 끝남)와 가짜 키 보관함으로 온보딩 단계 이동(다음, 이전, 안내 건너뛰기, 키 단계 있음·없음)을 앱 시험으로 확인하고, 안내 장 셋을 스냅샷으로 찍는다. 새 사용자 첫 실행은 사람이 macOS 새 사용자 계정에서 본다(spec 004 위험 6과 같은 방법).

**Acceptance Scenarios**:

1. **Given** 온보딩을 끝내지 않았고 키 단계가 있다, **When** 앱을 처음 켠다, **Then** 온보딩 쪽 순서는 1/6 노치 안내, 2/6 순위 안내, 3/6 첫 행동 칸 안내, 4/6 키, 5/6 일정, 6/6 기본값이다. (Q1 debate 3:0, 사용자 위임 2026-11-12. Q2 사용자 결정 2026-11-12)
2. **Given** 판단 기능이 꺼져 키 단계가 없다, **When** 앱을 처음 켠다, **Then** 순서는 1/5~3/5 안내 장, 4/5 일정, 5/5 기본값이다. (Q2 사용자 결정 2026-11-12)
3. **Given** 안내 장 하나가 보인다, **When** "다음"을 누르거나 Enter를 누른다, **Then** 다음 쪽으로 넘어가고 아무것도 저장되지 않는다. 셋째 안내 장의 "다음"은 첫 설정 단계로 간다.
4. **Given** 둘째나 셋째 안내 장이 보인다, **When** "이전"을 누른다, **Then** 앞 장으로 돌아간다. 첫 안내 장에는 "이전"이 없다.
5. **Given** 첫째나 둘째 안내 장이 보인다, **When** "안내 건너뛰기"를 누른다, **Then** 남은 안내 장을 건너뛰고 첫 설정 단계로 간다. 셋째 안내 장에는 "안내 건너뛰기"가 없다(다음이 곧 첫 설정 단계다). (debate 3:0, 사용자 위임 2026-11-12)
6. **Given** 안내 장을 본 뒤 설정 단계를 모두 끝낸다, **When** "시작하기"를 누른다, **Then** 온보딩 끝냄이 남고(spec 002 R-116) 다음 실행에는 온보딩이 보이지 않는다.
7. **Given** 안내 장을 보는 중에 온보딩 창을 빨간 버튼으로 닫았다, **When** 앱을 다시 켠다, **Then** 온보딩이 1/6부터 다시 보인다(지금 온보딩 창과 같은 규칙).
8. **Given** 키 단계(4/6)다, **When** 화면을 본다, **Then** 키 단계 문구와 동작은 spec 006 R-624~R-626 그대로이고 단계 표시만 바뀐다. 키 단계에는 지금처럼 "이전"이 없다(R-712).

### User Story 3 - 이미 쓰는 사용자가 설정에서 안내를 다시 본다 (Priority: P2)

온보딩을 오래전에 끝낸 사용자는 게이트가 무엇이었는지 잊었다. 도움말 탭 맨 위의 "안내 다시 보기"를 누르면 설정 창 위 시트로 안내 장 세 장이 다시 보인다. 마지막 장에서 "다 봤어요"를 누르면 시트가 닫히고, 키·일정·기본값은 아무것도 바뀌지 않는다. 업데이트 뒤에 따로 안내 장이 뜨지는 않는다.

**Why this priority**: 사용자 결정 (2)의 두 번째 부분이다. 도움말 탭(이야기 1)이 같은 내용을 글로 이미 주므로 P2다.

**Independent Test**: 온보딩을 끝낸 가짜 설정 저장소에서 "안내 다시 보기"를 눌러 시트가 열리고, 끝까지 넘기거나 esc로 닫아도 설정 저장소·키 보관함·할 일 저장소에 쓰기가 0건인지 앱 시험으로 확인한다. 시트 첫 장과 마지막 장을 스냅샷으로 찍는다.

**Acceptance Scenarios**:

1. **Given** 온보딩을 끝냈다, **When** 도움말 탭의 "안내 다시 보기"를 누른다, **Then** 설정 창 위에 시트가 열리고 첫 안내 장(노치)이 1/3으로 보인다. 키·일정·기본값 단계는 보이지 않는다. (Q3 debate 3:0, 사용자 위임. Q9 사용자 결정 2026-11-12)
2. **Given** 시트가 열려 있다, **When** 장을 넘긴다, **Then** "안내 건너뛰기"는 어느 장에도 없다. 첫 장이 아니면 "이전"이 있다. (debate 3:0, 사용자 위임 2026-11-12)
3. **Given** 시트가 셋째 장이다, **When** "다 봤어요"를 누른다, **Then** 시트가 닫히고 설정 창은 도움말 탭 그대로다. 설정 값, 키, 일정, 할 일, 온보딩 끝냄 표시는 바뀌지 않는다.
4. **Given** 시트가 열려 있다, **When** esc를 누른다, **Then** 3과 같이 시트가 닫히고 아무것도 바뀌지 않는다.
5. **Given** 시트가 열려 있다, **When** 설정 창을 닫는다, **Then** 시트도 함께 닫히고 아무것도 바뀌지 않는다. 다음에 설정 창을 열면 시트는 보이지 않는다.
6. **Given** 타이머가 도는 중이다, **When** 시트를 본다, **Then** 노치와 타이머는 그대로 돈다. 안내 장 그림은 가짜 값으로 그린 그림이고 실제 노치를 움직이지 않는다.
7. **Given** 이 기능이 들어간 버전으로 업데이트했고 온보딩은 전에 끝냈다, **When** 앱을 켠다, **Then** 안내 장은 뜨지 않는다. 도움말 탭과 "안내 다시 보기"로만 본다. (debate 3:0, 사용자 위임 2026-11-12)

### Edge Cases

- **온보딩 창과 시트:** 온보딩을 끝내지 않아 "Moka 시작하기" 창이 열린 채 설정 창에서 "안내 다시 보기"를 누르면, 시트는 설정 창 위에 그대로 열린다. 시트는 쓰기가 0건이라 온보딩 단계와 값에 영향이 없다. 온보딩 창은 그대로 둔다.
- **시트가 열린 동안 탭 요청:** 노치나 할 일 탭의 "키 확인"처럼 설정 창 탭을 바꾸라는 요청이 오면, 시트는 열린 채로 두고 탭은 시트 아래에서 바뀐다. 시트를 닫으면 바뀐 탭이 보인다.
- **시트를 두 번 열기:** 시트가 열린 동안에는 설정 창의 다른 조작을 막으므로 "안내 다시 보기"를 다시 누를 수 없다. 따로 막는 규칙이 필요 없다.
- **키 단계가 없는 온보딩:** 판단 기능이 꺼져 키 단계가 없으면 설정 단계는 일정, 기본값 둘이고 단계 표시는 n/5다. 안내 장 셋은 그대로 보인다. "안내 건너뛰기"는 일정 단계(4/5)로 간다.
- **키 없음과 순위 장:** 안내 장 글은 키가 있는지에 따라 바뀌지 않는다. 순위 장은 키가 있을 때와 없을 때를 한 장에 함께 말한다("키가 없으면 마감이 가까운 순으로 떠요"는 기본 탭 키 칸 문구와 같다).
- **열린 공급자가 하나뿐:** 도움말 "판단 모델과 키" 항목은 공급자 이름을 늘어놓지 않는다. 고를 수 있는 공급자는 기본 탭에서 보인다고 안내한다.
- **보내는 곳 호스트:** 도움말은 호스트를 적지 않고 기본 탭의 "판단을 받으러 보내는 곳"에서 보라고만 안내한다. 그래서 Microsoft 주소를 넣지 않아 호스트가 없는 경우도 따로 다루지 않는다. (debate 3:0, 사용자 위임 2026-11-12)
- **두 가지 중요도:** 일정의 중요도는 "조금·꽤·아주"이고 이유 줄의 중요도는 "낮음·보통·높음"이다(용어집 context impact). 도움말은 두 값을 같은 말로 섞지 않고, "할 일과 일정" 항목과 "이유 줄" 항목에 각각 따로 적는다.
- **인용 문구가 바뀜:** 화면 문자열이 바뀌면 그 문자열을 인용한 도움말 글도 함께 바뀌어야 한다. 인용은 화면이 쓰는 같은 상수로 만들고(R-705), 바뀐 줄을 스냅샷이 보인다.
- **숫자가 들어간 문구:** "1순위", "미룬 2번"처럼 숫자가 바뀌는 문구는 가짜 예시 숫자로 인용하고 숫자의 뜻을 글로 적는다. 시간 끝 다시 시작 버튼("N분 더")은 숫자를 박지 않고 "시간을 골라 이어 간다"로 쓴다. 이 버튼의 처음 값은 기본 작업 시간이다(`NotchTimer.swift:45`, `:98`의 `defaultQuantumMin`). 사용자의 실제 설정 값을 읽어 넣지 않는다.
- **설정 창 크기:** 설정 창 폭 460pt는 그대로다. 도움말 탭 본문이 창 높이를 넘으면 탭 안에서 세로로 스크롤한다. 다른 탭의 높이는 바뀌지 않는다. 시트는 설정 창 폭 안에 든다.
- **노치가 없는 화면:** 노치 항목은 노치가 없는 화면에서는 메뉴 막대 아래 가운데에 같은 판이 뜬다고 함께 적는다(spec 001 R-011).
- **동작 줄이기:** 안내 장을 넘길 때 움직임이 있다면 macOS "동작 줄이기"가 켜져 있으면 움직임 없이 바꾼다(spec 001 노치 애니메이션과 같은 기준).
- **다크 모드:** 안내 장 그림은 노치 판(검정)을 그리므로 라이트·다크 모두 같은 판 색이고, 창과 시트 배경만 설정 창 색을 따른다.
- **앱 DB를 열 수 없음:** 도움말 탭과 시트는 DB를 읽거나 쓰지 않으므로 그대로 보인다. 온보딩 끝내기 저장이 실패하는 경우는 spec 002 R-116 그대로다.
- **VoiceOver:** 안내 장 그림은 그림 하나마다 접근성 설명 한 줄을 둔다. 단계 표시는 지금처럼 "n/m단계"로 읽는다.

### 도움말 설명 (확정 시안 2~9번)

시안 확정 2026-11-13(사용자). 항목마다 5문장 이하다(R-704).

1. **노치** (5문장): 마우스를 노치에 올리면 펼쳐지고, 펼친 판을 한 번 누르면 글자를 적을 수 있어요. "무엇을 할까요?" 칸에 할 일을 적고 Enter를 누른 뒤, 시간을 골라 "시작"을 눌러 주세요. 타이머가 도는 동안 접힌 노치에 제목과 남은 시간이 보여요. 시간이 끝나면 노치가 펼친 채로 기다리니, "완료"를 누르거나 시간을 골라 이어 가거나 "미루기"·"바꾸기"를 눌러 주세요. 노치가 없는 화면에서는 메뉴 막대 아래 가운데에 같은 판이 떠요.
2. **할 일과 일정** (4문장): 할 일은 노치에서 바로 적거나 설정의 "할 일" 탭에서 +로 더하고, 두 번 클릭하면 고쳐요. "전체", "오늘", "이번 주"로 보기를 바꾸고 "만든 순", "마감 순"으로 정렬해요. 일정은 시험이나 제출처럼 할 일 순서에 영향을 주는 날이에요. "일정" 탭에서 이름, 날짜, 중요도("조금", "꽤", "아주")를 넣어요.
3. **순위와 "다음"** (4문장): "할 일" 탭에서 먼저 할 세 할 일에 "1순위", "2순위", "3순위"가 붙어요. "다음" 표시가 붙은 할 일이 노치에 떠요. 키가 있으면 판단 모델이 정한 순서이고, 키가 없으면 마감이 가까운 순이에요. "미루기"나 "바꾸기"를 누르면 그다음 순위의 할 일이 떠요.
4. **이유 줄** (5문장): 노치를 펼치면 제목 아래에 이 할 일이 왜 떴는지 한 줄로 보여요. 예를 들어 "D-3 · 중요도 보통 · 미룬 2번"은 마감까지 사흘 남았고, 판단 모델이 본 중요도가 보통이고, 두 번 미뤘다는 뜻이에요. "D-day"는 오늘 마감, "D+2"는 마감이 이틀 지났다는 뜻이에요. 판단 결과가 아직 없으면 중요도 칸은 빠져요. 이 중요도는 판단 모델이 매긴 값이라 일정의 중요도("조금", "꽤", "아주")와는 달라요.
5. **첫 행동 칸** (5문장): 어디서 시작할지 막연해 보이는 할 일이 시작 전으로 뜨면 노치가 "어디서 시작할지 막연해 보여요"라고 물어요. 지금 바로 손댈 첫 행동을 한 줄 적고 "적기"를 누르면 판단 모델이 다시 확인해요. 통과하면 제목 아래 "이어서 할 일"로 보여요. 세 번까지 묻고, 그 뒤에는 묻지 않아요. 바로 시작하고 싶으면 "지금은 넘기기"를 누르거나 "시작"을 눌러 주세요.
6. **판단 모델과 키** (5문장): 판단 모델은 할 일과 일정을 보고 무엇부터 할지 순서를 정해요. 설정의 "기본" 탭 판단 모델 칸에서 공급자를 고르고 키를 붙여 넣어 주세요. 키는 이 Mac의 키체인에만 저장되고 다시 보이지 않아요. 키가 없으면 마감이 가까운 순으로 떠요. "키가 맞지 않아 판단 모델에 묻지 못하고 있어요."가 보이면 "키 확인"을 눌러 키를 지우고 다시 저장해 주세요.
7. **보내는 곳** (4문장): 키를 넣으면 할 일 제목, 마감, 예상 시간, 이어서 할 일, 일정, 마지막으로 적은 두 줄이 판단 모델 서버로 가요. 다른 할 일과 미룬 횟수는 보내지 않아요. 어느 서버로 가는지는 "기본" 탭의 "판단을 받으러 보내는 곳"에서 볼 수 있어요. 보내고 싶지 않으면 키를 지워 주세요.
8. **단축 동작**: 아래 표의 앞 세 열을 그대로 보여요.

### Key Entities

- **도움말 항목**: 제목, 요약 한 줄, 설명 글. 앱 코드의 고정 값이고 저장하지 않는다. 인용 문구는 화면 문자열 상수로 만든다.
- **도움말 펼침 상태**: 펼친 항목의 집합. 탭 뷰 밖에 두고 저장하지 않는다(R-707).

- **온보딩 단계 목록**: 지금 `OnboardingSteps`의 쪽 목록(키, 일정, 기본값) 앞에 안내 장 셋이 더해진다.
- **온보딩 끝냄**: spec 002 `onboarding_done` 그대로. 시트는 이 값을 읽지도 쓰지도 않는다. 새 설정 키는 없다(R-715).

## Assumptions

- 사용자는 작성자 1인, macOS 14 이상이다. 열린 판단 공급자는 TypeSafe Jev 하나다(spec 006 R-617).
- 시간 끝 다시 시작 버튼("N분 더")의 N은 시간 칩 값이고, 처음 값은 기본 작업 시간이다(`Sources/MokaCore/NotchTimer.swift:45`, `:98`). 설정의 "추가 시간"(`default_extend_min`)은 저장만 하고 노치는 쓰지 않는다(spec 002 Assumptions "추가 시간은 저장만 한다"). 그래서 도움말은 "추가 시간"을 설명하지 않고, 이어 가기를 "시간을 골라 이어 간다"로 쓴다.
- Q8의 "실제 뷰 부품" 조건: `NotchContentView`는 AppState를 모르고 값과 콜백만 받는다(`App/Sources/Views/NotchContentView.swift:6`, ADR-0009). 그래서 안내 장 그림은 실제 뷰 부품에 가짜 값을 넣어 그릴 수 있고, 도형 그림으로 낮출 필요가 없다. 구현 중 어느 부품이 AppState에 기대는 것으로 드러나면 그 부품만 도형 그림으로 낮추고 구현 PR "가정"에 적는다.
- 첫 설정 단계(키 단계, 키 단계가 없으면 일정 단계)에는 "이전"을 두지 않는다. 지금 코드(PR #143)에 없는 버튼이고, 안내 장은 "안내 다시 보기"로 언제든 다시 볼 수 있어 돌아갈 길이 따로 있다. 시안 13번도 "이전" 없이 그렸다.
- 도움말 글의 "펼친 판을 한 번 누르면 글자를 적을 수 있어요"는 spec 001 R-002(마우스를 올려 펼칠 때는 포커스를 가져가지 않고, 클릭하면 받는다)를 사용자 말로 옮긴 것이다.
- 보내는 곳 항목의 "무엇이 가는지" 목록은 `JudgmentState`(판단 입력)의 칸 그대로다: 오늘 날짜·요일, 할 일 제목·마감·예상 분·첫 행동, 일정 이름·날짜·중요도, 그 할 일의 마지막 체크포인트 두 줄. 다른 할 일, 미룬 횟수, 할 일 id는 넣지 않는다(헌법 VIII). 판단 입력 칸이 바뀌면 도움말 글도 바꾼다.
- "단축 동작" 표의 ⌘,와 ⌘Q는 메뉴 막대 Moka 메뉴가 열려 있을 때의 키다. 전역 단축키가 아니다.
- 도움말 탭 아이콘(물음표 원)과 탭 순서(도움말이 맨 끝)는 작은 가정이었고 확정 시안 1번으로 확인됐다(2026-11-13).
- 시트에 "이전"을 두는 것은 온보딩 안내 장과 같은 규칙을 따른 작은 가정이다.
- 승인 항목(헌법 I): 이 spec은 스키마, 질문 파일, 판단 공급자 경계, 시뮬레이터 시나리오 형식, 로그 값 집합, 의존성, CI, 설정 키를 바꾸지 않는다(Q10으로 새 설정 키도 없다).

## Non-Goals

- 새 단축키, 전역 단축키.
- 실제 노치 위에 겹쳐 가리키는 코치 표시.
- 도움말 검색, 바깥 웹 문서, 영어 도움말.
- 화면 문구 자체를 바꾸기. 도움말은 지금 화면 글자를 인용만 한다(아래 위험 6의 추가 시간 안내 문구도 이 spec에서 고치지 않는다).
- 행동 로그에 도움말·안내 장 조작을 남기기(새 사용자 행동 값은 공개 계약 변경).
- 공급자마다 키 받는 방법을 도움말에 따로 적기. 키 받기 링크는 기본 탭에 이미 있다(spec 006 R-620).
- 업데이트한 기존 사용자에게 안내 장이나 새 기능 알림을 따로 띄우기(R-715).
- 마일스톤 4·5 기능(스케줄러, 이월 카드, 불확실 질의)의 설명. 기능이 생기는 spec에서 도움말 항목을 더한다.

## 대안과 위험

대안:

| 결정 | 기각한 안(한 줄 이유) | 근거 |
|---|---|---|
| 인용 문구는 화면 상수에서 만듦 | 도움말 글에 글자를 따로 적음(화면 글자가 바뀌면 도움말만 옛 글로 남고 알아챌 길이 없음) | SC-703 |
| 도움말은 지금 있는 기능만 | 앞으로 생길 기능도 미리 적음(없는 화면을 설명해 헷갈림) | Non-Goals |
| 안내 장 글은 키 유무와 상관없이 같음 | 키 유무에 따라 순위 장 글을 바꿈(온보딩 중 키 단계 앞뒤로 같은 장이 달라질 수 있음) | Edge Cases |
| 다시 보기는 설정 창 위 시트(사용자 결정 2026-11-12) | 온보딩과 같은 모양의 별도 창(이미 열려 있을 때 앞으로 올리기, 빨간 버튼 처리가 더 필요함), 도움말 탭 안에서 장 넘김(목차와 안내 장이 한 화면에서 섞임) | debate 기록 Q9 |
| 버튼은 도움말 탭 맨 위(debate 3:0) | 기본 탭 맨 아래(설정 값 사이에 읽기 전용 동작이 섞임), 메뉴 막대(spec 001 R-012 메뉴 항목 둘 규칙과 어긋남) | debate 기록 Q5, spec 001 R-012 |

위험:

- 위험 1(글이 낡음): 화면 문구는 상수 비교 시험으로 지키지만, 동작 설명(예: "세 번까지 물어요")은 시험이 지키지 못한다. 규칙을 바꾸는 spec은 도움말 항목도 함께 고쳐야 한다. 구현 PR에서 도움말 항목마다 근거 R 번호를 시험 이름에 남겨 찾게 한다.
- 위험 2(온보딩이 길어짐): 안내 장 셋을 더해 새 사용자가 시작까지 넘기는 쪽이 3에서 6으로 늘어난다. "안내 건너뛰기"로 조작은 한 번만 는다(SC-704).
- 위험 3(스냅샷 변경): 탭 줄과 단계 표시가 바뀌어 기존 설정 창·온보딩 참조 이미지가 다시 찍힌다(SC-707). 바뀐 이미지가 탭 줄·단계 표시 밖까지 바뀌었는지 사람이 PR에서 본다.
- 위험 4(사람 확인): 첫 실행 온보딩은 새 사용자 계정에서만 보여 사람이 macOS 새 사용자 계정으로 확인해야 한다(spec 004 위험 6). 다시 보기 시트는 지금 계정에서 확인할 수 있다.
- 위험 5(PRD와 다름): PRD FR-21은 첫 실행 온보딩을 설정 3단계(키, 일정, 기본값)로 적었다. 이 spec 뒤 첫 실행은 안내 장 셋을 더해 6단계(키 단계가 없으면 5단계)가 된다. PRD는 저장소 밖 문서(`~/Dev/ai-platform/projects/moka/prd.md`)라 사람이 고친다. 고칠 문장: FR-21의 첫 실행 단계 수와 순서.
- 위험 6(화면 문구와 동작이 다름, 이 spec 밖): 기본 탭 "추가 시간" 안내 "시간이 끝났을 때 더 이어 갈 시간이에요."(`App/Sources/Views/BasicTabView.swift:30`)와 달리, 시간 끝 이어 가기 버튼은 기본 작업 시간을 처음 값으로 쓴다(`Sources/MokaCore/NotchTimer.swift:45`, `:98`). spec 002는 추가 시간을 "저장만 한다"고 적었다. 도움말은 추가 시간을 설명하지 않아 이 차이를 키우지 않는다. 안내 문구를 고칠지, 이어 가기에 추가 시간을 쓸지는 별도 작업으로 사람이 정한다([Issue #151](https://github.com/DongWonLee2/moka/issues/151)).
